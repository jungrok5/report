# 보고서 읽기 화면 재검토

ai-design 1.2.0의 글·UI 기준을 적용한 뒤에도 남은 반복 형식을 화면에서 검토했습니다. 제목 → 무슨 일이 있었나·공통 시간축 → 원인 → 조사 기록 → 인과관계·근거 순서는 유지합니다.

| 남아 있던 문제 | 반영 |
| --- | --- |
| 범례가 세 개의 큰 수치 영역으로 보임 | 선 색·모양, 지표 이름, 실제 관측 범위를 한 줄 범례로 표시 |
| 원인이 짙은 강조 상자에 갇힘 | 구분선과 본문 크기로 구분하고 현재 판정은 글자로 표시 |
| 조사마다 같은 ‘확인한 사실 / 판정’ 라벨 반복 | 실제 질문과 관측·판정 문단으로 구성 |
| 긴 사건 목록과 설명이 원인 요약을 밀어냄 | 사건 목록·조작 방법을 펼쳐 확인; 그래프 툴팁에도 가까운 사건의 실제 시각·이름 표시 |
| 독립 HTML의 단계별 근거 브라우저가 본문을 반복 | 단계별 근거는 펼쳐 확인하고 인쇄 기록에는 전체 근거 보존 |

React 화면과 독립 HTML 템플릿에 함께 적용했습니다. 원본 JSON, 수치·시각, 원인 후보와 상태, 조회 URL, 보존본, 검토·버전 기록은 수정하지 않았습니다. 닫힌 판정 범위가 인쇄에서 누락되지 않도록 React 인쇄본에는 별도 판정 범위를 포함합니다.

검증: 스타일 0 오류·0 경고, Python 43개·모델 7개 테스트, 재생 산출물·보존본 바이트 비교, 세 가상 보고서의 1100·390·320px 조작·근거·버전·import·인쇄 검사, 독립 HTML·조사 엔진 HTML의 1024·390·320px 검사, 라이트·다크 375·768·1024·1440px 넘침·원인 본문 대비·인쇄 대비 검사, 빌드 통과. 데스크톱과 모바일 화면도 직접 검토했습니다. 설치된 스킬의 렌더러와 저장된 예시 HTML의 바이트 일치도 확인했습니다.

이 검증은 화면과 기능에 대한 확인입니다. 실제 운영 장애의 인과관계나 수신팀의 이해도를 검증한 결과는 아닙니다.
