## 사용자 선호 때문에 유지한 설계

원인을 현상보다 앞에 옮기거나 시간 그래프를 여러 개로 나누는 권고는 채택하지 않았다. 하나의 시간축에 색·선 모양으로 겹치고 실제 값·단위·원본 표본 시각·집계 설명을 툴팁으로 보여준다. 상대 높이는 용량 사용률이 아니며 실제 관측 범위를 범례에 표시한다. 안정적인 DB 선도 위쪽에 놓일 수 있어 실제 범위와 설명을 함께 읽어야 한다. null과 공백은 선을 끊고 보간하지 않는다.

현상 그래프를 원인보다 위에 두면 첫 화면에 원인까지 모두 들어가지 않을 수 있다. 긴 조작 설명·파일 도구는 접고, 현상 prose와 원인 요약을 기본 공개했다. 데스크톱 한 화면에 모든 핵심이 보인다는 수용 기준은 아직 충족했다고 주장하지 않는다.

## 남은 중요한 경계

1. **실제 장애 검증:** 세 사례는 합성 자료다. 실제 과거 장애 3건, 담당팀이 추가 설명 없이 결론·근거에 도달하는지의 검토, 모델의 가설 품질·운영 조회 정확도는 아직 검증하지 않았다.
2. **근거와 주장 의미 일치:** SHA-256·형식·DAG 통과는 원인의 진실을 입증하지 않는다. 수동 imported report sample/metrics/events를 archive에서 재생성하여 자동 대조하는 범용 파서는 없다. 인용한 보존본 전체를 확인해 주장·집계·범위·인과 방향을 사람이 검토해야 한다. 합성 표시를 지운 임의 보고서의 출처 진위를 인증하는 기능도 없다.
3. **검토자의 신원:** 구조가 올바른 unsigned 메타데이터는 위조할 수 있다. 표시된 approved는 파일에 기록된 검토 상태이며 조직의 인증된 승인으로 해석할 수 없다. 운영 도입에는 인증된 저장소 API 또는 신뢰할 수 있는 서명이 필요하다.
4. **완전성 선언:** coverage_complete는 제공자/운영자의 확인 기록이다. 코드가 실제 파이프라인의 정상·누락 없음·쿼리 대상 범위를 자동 입증하지 않는다. 누락·부분 시간은 선언으로 우회할 수 없지만 선언 자체의 진위는 외부 근거가 필요하다.
5. **AI 가시성:** 대표 시계열과 극값이 모든 이상 패턴을 포함하지는 않는다. 긴 로그 원본을 chunk로 추가 읽는 도구는 없다. 해당 자료에서 전 구간 부재·배제를 금지하고 추가 원본 확인을 남긴다. context 보존은 모델이 받은 자료의 기록이지 모델 응답 정확도의 증명은 아니다.
6. **재현 자료:** DB 합성 대조 예시는 수치 요약이며 실제 run/스크립트·환경·반복 원본이 없다. 이 한계를 E_test에 직접 표시했다. 실제 verified 판정에는 검증 대상·조건·절차·환경·실행 기록·결과·반증과 검토가 필요하다.
7. **전달 형태:** 모바일 그래프 자체는 여전히 확대가 필요하다. 읽기 대안은 연속 본문·노드 목록이다. 전체 근거 JSON을 포함한 PDF는 길어질 수 있다. 특정 조사/근거 위치를 직접 공유하는 URL은 아직 없다.
