# 한국어 장애 보고서 문체

첫 요약에서 원인 또는 가장 유력한 후보를 구체적으로 명명한다. `시스템적인 이슈`처럼 정보 없는 표현을 피한다. 대상, 동작, 대기 자원, 유저 영향의 관계를 짧은 문장으로 연결한다.

관측에는 `동시에 증가했다`, 후보에는 `유력한 후보다`, 검증된 관계에는 `차단했다`를 쓴다. 근거 없는 `분명히`, `완벽하게 입증`, `99%`를 쓰지 않는다.

`DB가 느렸다`에서 멈추지 않는다. 어떤 요청이 무엇을 기다렸는지와 근거를 설명한다. 코드·쿼리는 상세 근거에 넣고 요약은 비개발자도 읽게 쓴다.

검증을 `A라면 B가 관측되어야 합니다. C를 조회했고 D를 확인했습니다. 따라서 E로 판단했습니다. F는 미확인이고 다음으로 G를 확인합니다.`로 구성한다. 그대로 반복하지 않고 필요한 부분을 자연스럽게 연결한다.

코드, 설정, 절차와 시스템 조건을 설명한다. 책임팀·조치 담당자는 기록하되 개인 탓으로 결론을 대신하지 않는다. 영어 요청 시 evidence ID, 숫자, 시간대, 상태를 유지한다.
