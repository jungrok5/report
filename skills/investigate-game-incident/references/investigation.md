# 장애 조사 절차

## 관측의 신뢰성

동접 집계와 수집기가 정상인지 먼저 확인한다. 클라이언트 프레임, 네트워크 왕복, 서버 틱, 요청 지연을 구분한다. 호스트가 살아 있어도 업무가 멈출 수 있고 메트릭이 사라져도 프로세스 종료로 단정할 수 없다.

발생 시각, 수신·조회 시각, 조사 시각을 구분한다. 원래 시각과 timezone을 보존하고 표시 시간대만 통일한다. 시계 오차가 이벤트 간 간격보다 크면 선후 관계를 미확인으로 남긴다. 수집 간격보다 정밀한 시각을 만들지 않는다.

## 범위와 비교

영향 지역·월드·호스트·버전·플랫폼·ISP를 분리한다. 정상 월드와 비교하고 배포·작업·설정 변경을 시간축에 올린다. 시간·범위·요청 종류로 서버 측 필터링한다. 정상 범위는 실제 기준 구간과 함께 제시한다.

## 가설 검증

질문 / 가설 / 예측 / 조회 / 관측 / 판정 / 다음 질문으로 기록한다. 후보를 확인하는 조회와 모순을 찾는 조회를 수행한다. 정보가 없으면 구체적인 다음 검증을 남긴다.

DB 락이 요청을 막았다면 blocker/waiter 관계가 있어야 한다. DB 시계열과 지연이 비슷하다는 것만으로 부족하다. 요청 span, 잠금 관계, 연결 풀 대기, 제거 뒤 회복, 대조 실험이 맞는지 본다.

재부팅 후 DB QPS가 급증했다면 시작 시각, 로딩 작업 ID, 쿼리 태그/지문, 요청 비중, 정상 재부팅의 부하를 확인한다. 재접속과 내부 로딩의 기여율은 분리한다.

## 상태

- `observed`: 직접 관측한 사실. 그 사실의 원인은 별도다.
- `verified`: 메커니즘의 직접 근거와 검증이 일치한다. 검증 이유를 적는다.
- `supported`: 현재 증거가 지지하지만 대안·누락이 남는다.
- `unknown`: 정보가 없어 판정하지 못한다.
- `excluded`: 특정 시간·범위·경로에서 배제했다. 전체 가능성을 부정하지 않는다.

예외 로그만으로 모든 종료를 설명하지 않는다. 프로세스 ID·종료 코드·dump·시각을 결합한다. 재부팅 후 회복만으로 근본 해결이라고 쓰지 않는다. 조치가 동시에 실행됐다면 효과를 분리했다고 주장하지 않는다.

## 확정

결론, 반증·한계, 영향, 복구 결과, 후속 조치를 적는다. 조치마다 담당·기한·완료 기준을 둔다. 직접 원인이 확인돼도 보상 누락이나 종료 사유 기여율은 별도 미확인일 수 있다. 판단이 바뀌면 버전을 올리고 기존 근거를 보존한다.
